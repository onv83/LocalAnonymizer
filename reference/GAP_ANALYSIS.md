# Gap analysis: корпоративный референс → LocalAnonymizer

Дата исследования: 2026-09-14

Источник исследован в **Яндекс Браузере** в авторизованной сессии. Для анализа поведения локально сохранён DOM страницы (`reference/astralinux-page.html`). В продукт не переносятся брендинг, Confluence-обвязка, тексты справки или сторонние assets.

## Что подтверждено у референса

### Основной сценарий

- Две синхронные панели: исходный текст и обезличенный результат.
- Автоматический пересчёт с задержкой после ввода.
- Импорт `.docx`/`.doc`, drag-and-drop и кнопка с демонстрационным примером.
- Синие обратимые маркеры, серые необратимые удаления секретов, жёлтые кандидаты.
- Навигация стрелками по всем найденным фрагментам и визуальное выделение активного фрагмента в обеих панелях.
- Клик по синему маркеру возвращает исходное значение в текущий результат; последнее действие можно отменить.
- Для жёлтого кандидата доступны решения «Оставить» и «Скрыть»; показывается прогресс проверки.
- Таблица соответствий сворачивается, содержит маркер/тип/исходное значение; клик по строке переводит к соответствующему фрагменту.
- Копирование результата, выгрузка `.txt`/`.docx`, очистка формы, пакетная выгрузка готовых документов в ZIP.
- Горячие клавиши: `Ctrl+Enter` для копирования, двойной `Esc` для очистки.

### Настройки и словари

- Категории включаются отдельно; обработка секретов принудительно включена.
- Параноидальный режим добавляет консервативные кандидаты вместо безусловного удаления неоднозначных значений.
- Пользовательские правила формата `фраза => ТИП`.
- Whitelist исключает точные значения из замены.
- Профили словарей, импорт/экспорт настроек, сброс и self-test.
- Настройка моноширинного шрифта и сохранение локальных предпочтений.

### Движок

- Сначала собираются кандидаты по исходным координатам, затем централизованно разрешаются пересечения, после чего выполняются замены справа налево.
- Маркеры стабильны в пределах одного прогона; алиасы полного ФИО/организации повторно используют тот же маркер.
- Детекторы: секреты и токены, ФИО и формы имён, организации и системы, почта/телефон/аккаунты, домены/IP/CIDR/MAC/URL, задачи/CVE, ИНН/КПП/СНИЛС/БИК/счета/карты/паспорт/VIN/кадастр/госномер/табельный/договор, суммы/ставки, адреса и дата рождения.
- Дополнительный warning scan: возможная гостайна, ДСП/ДПСП, КИИ, ОКПД2/КТРУ и признаки массива персональных данных.
- Известные публичные значения (например версия платформы, SLA/НДС и явно названный порт) исключаются контекстными правилами.
- Демонстрационный пример в проверенной версии показал 42 срабатывания, 6 жёлтых кандидатов и 33 обратимых записи.

### Ограничения референса

- Состояние и словари хранятся в браузере, а не в отдельной DPAPI-защищённой документной базе.
- DOCX обрабатывается браузерной XML-логикой; сложные OOXML-объекты требуют ручной проверки.
- Присутствуют зависимости окружения страницы; это неприемлемо для полностью автономного рабочего места.

## Исходное состояние LocalAnonymizer

Преимущества, которые сохраняются:

- полностью локальный `pywebview`, без HTTP-сервера/CDN/сетевых запросов;
- постоянная библиотека документов;
- отдельная DPAPI-защищённая mapping-таблица, привязанная к документу и операции;
- `.doc`, `.docx`, `.xlsx`, `.txt`, `.csv`, `.md`, `.log`;
- безопасное восстановление после внешней обработки и отчёт о неизвестных маркерах;
- fail-closed предупреждения для непроверенных OOXML-частей;
- удаление метаданных, комментариев, external relationships, tracked deletions и hidden runs;
- CSV formula neutralization;
- исходник не изменяется, публикация результата атомарна.

Зафиксированные расхождения до доработки:

| Область | Было локально | Требуемое изменение |
|---|---|---|
| Автоматический анализ | только явная кнопка | debounce-анализ во время ввода |
| Результат | обычный `textarea` | rich view с синими/серыми/жёлтыми span |
| Навигация | стрелки только по кандидатам | единая навигация по заменам и кандидатам |
| Ложное срабатывание | ручного возврата нет | клик по маркеру + одношаговая отмена |
| Кандидаты | список строк | карточка решения «Оставить/Скрыть» и прогресс |
| Подсветка исходника | нет | синхронный mirror с текущим фрагментом |
| Алиасы и контекст | базовые | расширенные формы ФИО/организаций/систем |
| Секреты | основные шаблоны | слабые пароли, bearer/JWT/tokens/keys/credentials |
| Технические/финансовые типы | базовые | БИК, паспорт, VIN, hostnames и дополнительные контексты |
| Warning scan | отсутствовал | отдельные безопасные предупреждения |
| Пакетный экспорт | отсутствовал | ZIP только с обезличенными файлами, без mapping |
| Статистика | по уникальным mapping | общее число замен, уникальная legend, hints, secrets |

## Критерии приёмки доработки

1. Существующие 21 тест проходят без ослабления проверок.
2. Добавлены RED→GREEN регрессионные тесты для новых детекторов, parts/offsets, секретов и batch ZIP.
3. В пользовательском acceptance sample подрядчик становится организацией, `АС «…»` — системой, учётная запись — логином, слабый пароль удаляется без mapping.
4. Версия `1.7.5.16`, `SLA 99,9%`, `НДС 20%` и порт `8080` остаются без изменений.
5. В UI отображаются три вида срабатываний и работают навигация, возврат, отмена и решения по candidates.
6. Mapping остаётся DPAPI-защищённой и отдельной для каждого документа.
7. ZIP не содержит исходники, mapping или служебную БД.
8. После сборки проходят полный pytest, EXE `--smoke` и документный e2e smoke.
9. Результат DOCX/XLSX с предупреждениями не выдаётся как безопасный без ручной проверки.
